## D-4 가설 검증: `자파리 → life-7`

가설: "자파리(장난)를 `life-7`(놀이)로 옮기면 people-4에 무삭제로

- `life-7`의 실제 구성원 9개 중 "놀이/장난" 개념과 일치하는 단어가

  원문 근거(빈도 15·장난)로 손수 작성된 예문(`content/examples.json`
  `5404-1`)이 있다 — **이동/제거 비용이 높은, 확실히 확인된 단어**다.
  옮길 이유 자체가 약하다(제자리에 있어도 문제 없음).

**결론: `KEEP_IN_PLACE`.** 자파리는 people-4에 그대로 둔다.

### 결정적 발견 — `어느제2`와 `어느제1`의 완전 중복

`talk-3`의 `어느제2`(90294, 부사, "언제")와 `people-3`의 이미 배치된
`어느제1`(90122, 대명사, "언제")를 원자료(`bookMeta.definition`)로
대조했다:

- 어느제1: "1) (의문문에 쓰여) 잘 모르는 때를 가리키는 말. 2) 때가
  특별히 정해지지 않았음을 나타내는 말."
- 어느제2: "1) (의문문에 쓰여) 잘 모르는 때를 물을 때 쓰는 말. 2) 때가
  특별히 정해지지 않았음을 나타내는 말."

**같은 표기("어느제"), 같은 표준어("언제"), 사실상 동일한 뜻풀이** —
2025년 책이 품사(대명사/부사)만 다르게 나눠 번호를 붙인 동일 항목이다
(3C-1.2가 `이추룩/그추룩` 등에서 이미 본 것과 같은 유형의 "이미
가르치고 있는 개념의 재분류"). `어느제1`이 이미 people-3에 배치돼
있으므로 `어느제2`를 talk-3에 별도로 두는 것은 **같은 단어를 두 번
가르치는 것**과 다름없다.

`저펜`과 달리 `어느제2`는 다음 4개 근거를 **더 명확하게** 충족한다:

1. **주제 불일치 없음(중립)** — talk-3("표현")은 원래 의문·정도 부사가
   섞인 유닛이라 "언제"류 부사가 있는 것 자체는 어색하지 않다.
2. **개념 중복 — 이번 감사 중 가장 명백한 사례**: `어느제1`과
   원자료 정의가 사실상 동일하다.
3. **사용 근거 없음**: unconfirmed, exact 0.
4. **투자된 콘텐츠 없음**: `pendingExample: true`.

`이레1`·`저레`·`복삭`·`요레`처럼 "방향/의태 부사 군집이라 개념이
겹칠 수 있다"는 **추정** 수준이 아니라, `어느제2`는 원자료 정의
문장이 사실상 동일해 **중복이 확정적**이다. 이 때문에 3C-2의 원래
제안(`이레1` 교체)보다 `어느제2` 교체가 근거가 더 강하다 — 3C-2
단계에서는 talk-3·talk-4 전체를 열어보지 않아 이 항목을 놓쳤다.

`복삭`은 3C-2에서 교체 후보로 거론됐으나 이번에 `confirmed`(17건)로
확인돼 **후보에서 제외**한다 — 사용 근거 하나만으로 유지/교체를
정하지 않는다는 원칙(D-9)에 따라 다른 근거(주제 불일치·개념 중복)도
없는 `복삭`을 건드릴 이유가 없다.

`이레1`·`저레`·`요레`는 방향부사 군집(이레저레·영·경·졍 등)과
느슨하게 겹치지만, **원자료 정의가 서로 다르다**(이/저/요 각각의
지시 대상이 다름 — "이곳/저곳/요곳") — 3C-1.2가 `그추룩`류에 적용한
"진짜 같은 개념" 기준을 그대로 적용하면 이들은 `이짝/저짝`처럼
독립적인 학습 가치가 있는 변이형에 더 가깝다. 억지로 유사하다고
묶지 않는다(D-8 지시대로).

두 항목 모두 **`RELOCATE_AND_ADD`(무삭제 이동)를 1순위로 실제 조사했으나

방향대명사·의문부사 개념에 맞는 이동처가 없었다(자세한 근거는 위
"D-4 가설 검증"·"자유 슬롯 유닛 실제 구성" 참고). 따라서 순수
`RELOCATE_AND_ADD`는 `NO`이고, 대신 **"교체 대상을 삭제하지 않고
`pendingPlacement`로 되돌린다"는 절충안**을 제안한다 — 이는
`content/lexemes.json`에서 완전히 지우는 것보다 훨씬 보수적이며
(`AGENTS.project.md`의 "근거 없는 기존 lexeme 삭제 금지" 원칙과
정합), 이미 57개가 이 상태로 안전하게 존재하는 검증된 메커니즘을
그대로 재사용한다. 향후 이 두 단어에 대한 근거가 강해지면 다시
유닛에 배치할 수도 있다(완전 삭제보다 되돌릴 여지가 있다).

## 삭제 없이 해결 가능한가?

```text
NO — 완전 무삭제(순수 이동만으로 두 CORE 단어를 배치)는 불가능했다.
```

이유: 9개 자유 슬롯 유닛(`people-8`, `body-2`, `body-7`, `food-3`,
`food-7`, `verbs-8`, `verbs-9`, `home`(adj-8), `life-7`)의 실제
구성원을 전수 확인한 결과, `people-4`/`talk-3`에서 뺄 후보 단어(저펜·
어느제2 포함, `자파리`·`장시`·`복삭` 등 검토했던 다른 후보 전부)가
자연스럽게 옮겨갈 만한 자유 슬롯 유닛이 하나도 없었다(유닛 제목과
실제 내용이 이미 어긋나 있어 "이름이 비슷하니 옮기면 되겠다"는 추정이
전부 기각됐다).

다만 실행 방식을 **"하드 삭제" 대신 "`pendingPlacement`로 되돌리기"**로
바꾸면, `content/lexemes.json`에서 표제어 자체가 사라지는 일은 없다 —
유닛 배치 그리드에서만 빠지고 원장에는 남는다. 이 의미에서는
"삭제 없이 해결 가능"이라고 볼 수도 있다.
