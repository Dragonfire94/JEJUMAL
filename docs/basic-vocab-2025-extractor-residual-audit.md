# 2.5단계 — extractor 잔여 무결성 문제 정밀감사

`docs/basic-vocab-2025-extractor-fix.md`(2단계)가 미해결로 남긴 두 가지를
마저 조사한 기록: 고급/명사 +1(266 vs 공식 265), old→new diff의
"완전 유실/형태 변경 추정" 44건. PR #3(`codex/basic-vocab-extractor-fix`)의
같은 브랜치에 추가 커밋했다. `content/*`, 앱 코드, 예문, 음원은 이번에도
건드리지 않았다.

## 1. 결론

- **최종 entry 수: 1,501개(변경 없음).** 고급/명사 +1의 원인을 코드
  버그로 특정하지 못했다 — 아래 2절의 증거에 따라, PDF 본문에는
  실제로 266개의 독립된 명사 entry가 인쇄되어 있고, 책 자신이 인쇄한
  요약표(p.102)의 "265"가 실제 본문과 어긋난다는 결론을 채택한다.
- **실제 parser 회귀/유실: 0건.** 44건을 전수 재조사한 결과 전부
  "구 extractor의 잘못된 병합이 새 extractor에서 정상적으로 풀린 것"
  (분류 A)이었다 — 44건 중 컴포넌트 형태 하나하나가 전부 새
  vocab.json 어딘가에 뜻과 함께 살아있음을 확인했다. E(진짜 유실),
  F(불확실)는 0건.
- 조사 과정에서 이번 항목과 무관한 실제 버그 하나(동형이의어 번호가
  쉼표로 묶인 여러 표준어 전체에 잘못 적용되던 문제)를 찾아 고쳤다 —
  count에는 영향 없음.

## 2. 고급 명사 +1 조사 결과

### 시도한 가설과 결과

**가설 A(과분리) — 기각.** 고급 명사 챕터(PDF p.103~124, 44개 반쪽)의
표준어 칸 줄 간격을 전수 측정했다:

| 구분 | n | min | p25 | median | p75 | max |
|---|--:|--:|--:|--:|--:|--:|
| 같은 entry 안 줄 간격 | 309 | 1.3 | 1.3 | 5.5 | 5.5 | 5.5 |
| 새 entry로 넘어가는 간격 | 222 | 32.8 | 37.8 | 38.5 | 39.1 | 162.3 |

두 분포 사이에 **27pt의 완전한 공백**이 있다(5.5~32.8pt 사이에 아무
것도 없음) — `NEW_BLOCK_GAP_PT=15`는 이 공백 한가운데 있고, threshold를
6~32 사이 어느 값으로 바꿔도 결과가 똑같다. 10~25pt 구간에 걸치는
경계 사례는 **0건**이었다. 즉 현재 266개 중 gap 임계값이 애매해서
잘못 갈라진 항목은 없다.

**가설 B(챕터 표지/오인) — 기각.** 266개 전체(정의 전문·제주어형·
페이지)를 직접 나열해 읽었다(`scratchpad/audit25/gn_full.txt`,
재현 방법은 9절 참고). 표지·주석·부록 텍스트가 섞인 항목은 없었다.
동일 정의문 완전일치·부분일치(유사도 0.5 이상) 검사에서도 실제로는
전부 서로 다른 단어인 근연 항목(예: "눌"/"눌굽", "양에"/"어욱")이었지
표지 오인은 아니었다. reverseIndex 대조 결과, 고급 명사의
표준어 대응 항목 206개 전부가 reverseIndex에 존재했고(누락 0건),
반대로 reverseIndex의 book p.204~247(고급 명사 챕터 전체 book
페이지 범위) 구간 표준어 208개 중 우리 목록에 없는 건 "고물"
1건뿐이었는데, 이는 실제로 우리 `jbv2025-1130`(표준어 "고물, 소2")의
"고물" 부분이라 — 데이터 유실이 아니라 동형이의어 번호 파싱
버그(3절)였다. source region 중복(같은 좌표의 텍스트가 두 번
추출됨)도 0건 확인.

**가설 C(공식 표 오류) — 채택.** 위 두 가설이 기각되고, 266개 전체를
직접 확인해도 이상이 없었으므로, 이번 조사에서 확보한 증거로는
PDF 본문 자체가 266개의 독립 entry를 담고 있다고 결론짓는다:

- 고급 명사 266개 전수 좌표 목록: `scratchpad/audit25/gn_diag.json`(재현 가능, 9절)
- 페이지별 개수: p.103~124, 10/13/12/10/12/12/13/12/11/12/13/13/12/13/13/11/13/12/14/12/13/10 (합 266)
- 표준어 대응 있음/없음: 206 / 60
- source region 중복: 0건
- 의심 split 전수 검토: 135→4 전부 오탐(5절), 그 중 고급 명사는
  1건(`ᄀᆞᆨ주와기/ᄀᆞᆨ줴기`, 44건 재조사에서도 D→A로 재확인, 정상
  병합 해제의 일부)뿐이고 나머지 3건은 형용사/부사
- reverseIndex 대조: 0건 누락, 1건은 버그(고물2)로 설명 완료

이 결론은 잠정적이다 — 책 원문에 있고 우리가 놓친 "265를 정확히
맞추는 또 다른 구조"가 있을 가능성을 완전히 배제하진 못한다. 그러나
5가지 독립적인 검증(gap 분포, 전수 읽기, 유사도 검사, reverseIndex
대조, source region 중복 검사) 모두 266이 맞다는 쪽으로 수렴했다.

## 3. 44건 분류

| 분류 | 개수 |
|---|--:|
| A 정상 병합 해제 | 44 |
| B 정상 재그룹 | 0 |
| C PUA/Unicode 차이 | 0 |
| D old 오류 제거 | 0 |
| E new parser 유실 | 0 |
| F 불확실 | 0 |
| 합계 | 44 |

44건 전부가 **A(정상 병합 해제)**다: 구 extractor가 서로 다른 여러
단어(때로는 품사·의미가 전혀 다른)를 표준어 칸 헤드워드 하나에
잘못 흡수시켰던 항목들이고, 새 extractor는 이를 좌표 구조에 따라
올바른 개수의 별도 entry로 풀어냈다. 44건 각각에 대해 구성 제주어형
전부가 새 vocab.json 어딘가에 원래 뜻과 함께 살아있음을 1:1로
확인했다(`scratchpad/audit25/classify44.txt`, 9절에서 재현 방법).

예시(`OLD id → 새 entry들`):
- `jbv2025-0808`(구, `['짠짠ᄒᆞ다','ᄒᆞ다','쪼끌락ᄒᆞ다','ᄒᆞ끌락ᄒᆞ다']`→`짜디짜다`) →
  새 `jbv2025-0875`(짠짠ᄒᆞ다/ᄒᆞ다=짜디짜다), 새 `jbv2025-0876`(쪼끌락ᄒᆞ다/ᄒᆞ끌락ᄒᆞ다=표준어없음).
  **`ᄒᆞ다`는 다른 챕터에서 "하다"(`jbv2025-0320`)로도 따로 나온다** —
  같은 글자가 서로 다른 두 단어에 재사용되는 정상적인 경우다(PUA
  glyph 재사용과 같은 패턴).
- `jbv2025-0928`(구, 7개 형태 뭉치→`수수`) → 새 `jbv2025-1021`(수수),
  `jbv2025-1022`(표준어없음, 바위), `jbv2025-1023`(표준어없음, 몸집),
  `jbv2025-1024`/`jbv2025-1025`(표준어없음, 농기구 2종) — 5개 서로
  무관한 단어가 하나로 뭉쳐 있었다.

44건 전부 A이므로 E/F 목록은 비어 있다. 6절(old→new diff)의 "완전
유실/형태 변경 추정 44건"이라는 이전 라벨은 부정확했음을 이 문서로
정정한다 — 132개 old-only 형태 조합 전부(88 + 44)가 병합 해제로
설명된다.

## 5. 수정 내용

동형이의어 번호 파싱 버그를 고쳤다(`build_entry_fields`). 이전에는
`standard_raw`가 "고물, 소2"처럼 쉼표로 여러 표준어를 나열하면서
**마지막 표기에만** 동형이의어 번호가 붙은 경우, 정규식이 문자열
전체를 하나로 보고 "고물"까지 2번 동형이의어인 것처럼 잘못 처리했다.
쉼표로 먼저 나눈 뒤 **마지막 조각에서만** 번호를 떼도록 고쳤다.
영향받은 항목 4개(`jbv2025-0034`, `0198`, `0327`, `1130`). entry
개수·구조에는 영향 없음(메타데이터 필드만 교정). 특정 단어를
하드코딩하지 않고 일반화된 파싱 규칙을 고친 것이다.

고급 명사 +1 자체는 코드를 고치지 않았다(2절 — 원인이 코드 버그가
아니라는 결론이므로 억지로 하나를 지우지 않았다).

## 6. 테스트 강화

`scripts/extract_jeju_basic_vocab_2025.test.mjs`를 다음과 같이 강화했다:

- 품사별 개수 테스트: "고급/명사 266 vs 공식 265"라는 알려진 예외를
  **그대로 유지**했다(2절에서 원인을 코드 버그로 확정하지 못했으므로
  strict assertion으로 못 바꾼다) — 다만 이 예외가 "미해결"이 아니라
  "조사 완료, 공식 표 오류로 잠정 확정"임을 주석과 이 문서로 명시했다.
- 병합 의심 휴리스틱 테스트: 상한(`<=10`)을 없애고, 남은 4건이 **정확히
  알려진 4개 id인지**(`jbv2025-0474`, `1038`, `1057`, `1495`)를 직접
  검사하도록 강화했다 — 새로운 의심 후보가 하나라도 생기면 실패한다.
- 혀/셋딸/셋아덜: `셋딸`이 독립 entry인지 별도로 assert 추가.
- 초급 수사: "하나~열" 10개 전체가 실제로 초급 수사 10개와 정확히
  일치하는지(부분 표본이 아니라 전수) 검사하도록 강화.
- 동형이의어 버그 회귀 방지 테스트 추가(`jbv2025-1130` "고물"이
  homograph 2번으로 잘못 표시되지 않는지).
