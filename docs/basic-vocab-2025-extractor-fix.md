# 2025 제주어 기본어휘 extractor 수정 + 1,500개 재추출 (2단계)

`docs/basic-vocab-2025-extractor-audit.md`(1단계 감사)에서 확정한 구조적
원인 2개를 고치고, `scripts/extract_jeju_basic_vocab_2025.py`를
재구성해서 `data/jeju-basic-vocab-2025/vocab.json`을 다시 뽑은 기록.
`content/lexemes.json`, `content/units.json`, 예문, 앱 UI, 퀴즈, 음원은
이번 단계에서 건드리지 않았다.

## 1. 한 줄 결론

원본 PDF의 1,500개 의미 단위 중 **1,501개**를 좌표 구조 기반으로
재현했고(알려진 병합 오류 6건 전부 해소, 자동 회귀 테스트로 고정),
품사별 개수는 19/20 카테고리가 공식 표와 정확히 일치하며, 남은 1건(고급
명사 266 vs 공식 265)은 원인을 확정하지 못해 억지로 맞추지 않고
정직하게 남겨뒀다.

## 2. 수정한 parser 구조

1. **표준어 대응 없는 제주 고유어 병합 문제.** 표준어 칸 줄 사이
   y좌표 간격을 실측하면, 같은 entry 안 연속 줄(문장 이어짐, 번호 매긴
   뜻풀이)은 1~6pt, 다음 entry로 넘어가는 지점은 37~40pt였다(헤드워드가
   있든 없든 동일). `parse_half()`가 "헤드워드 스타일 줄"뿐 아니라
   "이전 줄과 간격이 `NEW_BLOCK_GAP_PT`(15pt)를 넘는 줄"도 새 entry
   시작으로 인식하도록 고쳤다. 헤드워드가 없는 블록은
   `standard_raw: null, has_standard_equivalent: false`로 정직하게
   표시하고 표준어를 지어내지 않는다. **스키마 추가 필드**:
   `has_standard_equivalent`(boolean). `standard_raw: null`일 때
   `standard: []`, `standard_homograph_no: null`.
2. **우측 반쪽 품사/등급 라벨 미독.** 옛 코드는 좌측 여백(x 15~32)만
   읽었다. `read_margin_label()`로 좌/우 여백을 각각 읽고
   (`LEFT_MARGIN_X`/`RIGHT_MARGIN_X`), 반쪽 제주어 칸 맨 위에 찍히는
   인라인 "N. 품사명" 마커(`find_inline_pos_markers()`)가 있으면 그
   y좌표부터 품사를 바꾼다. 마커가 없으면 그 반쪽 전용 여백 라벨을,
   그것도 없으면 직전 상태를 이어간다 — 문서 전체를 책 읽는 순서로
   순회하며 `state`를 들고 다닌다(`parse_page_halves`).
3. **레벨 전환 구간 표지 오염.** 초급→중급→고급 전환 시 본문 칸
   한복판에 찍히는 "중급", "기본어휘500개", "1. 명사(215개)" 같은
   표지 텍스트가 사전 항목으로 잘못 파싱되던 문제를 `LEVEL_DIVIDER_RE`로
   필터링했다(3번 반복 측정 후 확정: 표준 형태 "N개"/"기본어휘" 단독
   줄, "표준어로 찾아보는" 부록 제목까지 포함하도록 넓혔다).
4. **PUA 확정 매핑 보존.** 1단계 이전 라운드에서 사람이 이미 확정한
   PUA→옛한글 복원(`pua-glyph-mapping.json`, confidence: "high" 58개)을
   재추출할 때마다 `restore_known_pua()`로 다시 적용한다 — 재추출은
   PDF 원문을 다시 읽으므로, 이 복원을 안 하면 이미 확정된 표기가 도로
   PUA 문자로 되돌아간다. medium(16)·low(7)는 이번 단계에서 건드리지
   않았다(entry 구조 수정과 PUA 판독 문제를 섞지 않는다는 원칙).

이 수정들 다 "알려진 오류 단어를 하드코딩으로 예외 처리"하는 방식이
아니라 **좌표 구조 자체를 다시 읽는** 방식이다. 알려진 오류 사례는
`scripts/extract_jeju_basic_vocab_2025.test.mjs`의 회귀 fixture로만
쓴다 — parser 본체에는 특정 단어를 언급하는 코드가 없다.

### 시도했다가 되돌린 것: 번호 매긴 뜻풀이 기반 분리

"표준어 대응 없음" 블록 중 "1) ... 2) ..."처럼 번호 매긴 뜻풀이가
여러 개 + 제주어형도 그 개수만큼 있는 경우(예: p.107 '주와기'=사마귀
곤충 / '줴기'=할퀴기 잘하는 사람이 한 블록에 묶임), "개수가 일치하면
서로 다른 entry로 쪼갠다"는 규칙을 한 번 넣어봤다. 그런데 이 규칙을
적용하면 오히려 **진짜 다의어·변이형** 항목(예: "덤방다/덤벙다"=
"풀이 무성하다/이슬이 맺히다"라는 한 형용사의 두 뜻, "자락/잘락"=
한 의태어의 두 뜻)까지 갈라져서 고급 형용사(100→101)·고급 부사
(65→67)·고급 명사(266→267, 오히려 더 나빠짐) 공식 개수와 어긋났다.
좌표(줄 간격)만으로는 "사마귀/줴기"류(다른 두 단어)와
"덤방다/덤벙다"류(한 단어의 두 뜻)를 구분할 신호가 없다 — 이 책은 후자
쪽으로 세고 있다는 뜻이므로, 의미 판단 없이 좌표만으로 더 쪼개는 시도는
되돌렸다(원칙 5-3: entry 경계는 좌표로, 의미 유사성은 의심 신호일
뿐). '주와기/줴기'가 실제로 다른 단어인지는 사람이 원문을 봐야 확정할
수 있는 잔여 사례로 남긴다.

## 5. 135개 의심 후보 재검사

1단계 감사에서 쓴 휴리스틱(`jeju_forms.length >= 2` AND 번호 매긴
뜻풀이 수보다 문장 조각 수가 많음)을 새 vocab.json에 재실행:

**135건 → 4건**으로 감소. 남은 4건을 전부 수동 확인한 결과:

|---|---|---|---|

| jbv2025-1038 | 두루막, 두루매기 | "고유 웃옷. 외출 시 입는다." | 정상 변이형(오탐) |

**아직 의심** 또는 **false positive 아님(진짜 병합)** 사례는 0건.
4건 전부 정상 변이형 철자를 휴리스틱이 "문장 2개=병합 의심"으로 오탐한

따라, 이 4건은 남겨두되 병합이 아님을 확인 후 테스트에 상한(≤10)으로
반영했다.

## 7. PUA 상태

| 시점 | PUA 포함 entry 수 |
|---|---|
| 수정 전(1,255개, 기존 라운드 PUA 수정 반영된 상태) | 57 |
| 재추출 직후(PUA 복원 재적용 전) | 494 |
| PUA 확정 매핑(high 58개) 재적용 후 | **59** |

재추출은 PDF 원문을 다시 읽으므로, 이전 라운드에서 사람이 확정한
PUA→옛한글 복원을 다시 적용하지 않으면 표기가 전부 원본 PUA로
되돌아간다(494개까지 치솟았던 것으로 확인). `restore_known_pua()`를
추가해 `pua-glyph-mapping.json`의 confidence: "high" 58개만 자동
재적용하도록 고쳤고, 그 결과 59개로 기존 수준(57개)에 근접했다(entry
수 자체가 1,255→1,501로 늘어 자연히 소폭 증가). medium 16개·low 7개는
이번 단계에서 건드리지 않았다 — 그대로 `pua-glyph-mapping.json`에
남아있다. **entry 구조 수정과 PUA 판독 문제를 섞지 않는다는 원칙을
지켰다.**

## 8. ID 안정성 영향

`content/lexemes.json`의 `bookMeta.bookId`가 `jbv2025-XXXX`를
참조하는 항목 655개를 새 vocab.json과 대조:

| 결과 | 건수 |
|---|---|
| bookId가 여전히 같은 제주어 단어를 가리킴 | 19 (2.9%) |
| bookId가 이제 **다른 단어**를 가리킴(드리프트) | 636 (97.1%) |
| bookId가 새 vocab.json에 아예 없음 | 0 |

현재 id(`jbv2025-{순번:04d}`)는 **순수 배열 순번 기반**이라는 게
확인됐다 — 재추출로 entry 246개가 새로 추가·재배치되면서 그 뒤 순번이
전부 밀려, 참조의 97%가 깨진다. **다음 단계에서 `content/`의
`bookId`를 마이그레이션하려면 이번 재추출 결과와 1:1 순번 대응을
가정하면 안 되고**, 제주어형+표준어+뜻풀이 조합으로 재매칭(6절의
diff 방법과 동일한 방식)해야 한다. **안정적인 ID 전략 제안**: 순번
대신 `(level, pos, 정규화된 jeju_forms 첫 항목, pdf_page)`나 뜻풀이
해시를 섞은 안정 키를 쓰면, 이후 entry가 추가/재배열돼도 기존 참조가
깨지지 않는다 — 이번 단계에서는 분석만 하고 실제 마이그레이션은 하지
않았다.
