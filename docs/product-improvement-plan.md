# JEJUMAL 제품 개선안

두 건의 외부 감사 문서(전체 감사·생활방언 활용방안 / 오픈소스 참고자료 활용방안)를 검토하고,
지적사항을 실제 코드·데이터에서 직접 재현·계측한 뒤 작성한 실행 계획이다.

- 기준 코드: `claude/jeju-dialect-education-feedback-2dtss7` (`22f3628`)
- 기준 데이터: `src/data/units.json` 1,000단어 / 100유닛, `data/life-dialect` 100편
- 계측 방법: 퀴즈 생성 로직을 그대로 재현해 20,000문항 시뮬레이션, 사전 원문 7,159항목 대조

---

## 0. 한 줄 요약

지금 병목은 기능이 아니라 **콘텐츠 정답성**이다. 앱은 작동하지만, 학습자가 맞는 답을
눌러도 틀렸다고 표시되는 문항이 존재하고, 뜻이 명백히 잘못 확정된 단어가 노출되며,
1,000개 예문이 사실상 두 개의 종결어미만 가르친다. 새 기능을 얹기 전에 이 세 가지를
먼저 막아야 한다.

## 1. 검증 결과 — 감사 문서 주장 대비 실측

감사 문서의 지적을 그대로 받아들이지 않고 전부 재현했다. 결과는 다음과 같다.

| 감사 문서 주장 | 실측 결과 | 판정 |
|---|---|---|
| 퀴즈에 복수 정답이 출현한다 (동의어 7개 예시) | 동의어 그룹 **46개 / 94단어**. 20,000문항 시뮬레이션에서 읽기 문제 **61건(0.30%)** 복수 정답 발생 | **사실, 문서보다 심각** |
| 듣기 퀴즈도 같은 문제 | 듣기 문제 복수 정답 **0건**. `uniqueTexts()`가 표준어 중복을 이미 차단 | **읽기 문제에 한정** |
| `턱사가리` 뜻이 틀렸다 | 사전 원문 `턱(理由)`, eng `reason`. 앱은 "턱"으로 가르치고 예문도 신체 턱 | **사실** |
| `선용` 뜻이 틀렸다 | 사전 원문 `=현용. 형사(形象)`, eng `something as it is now`. 앱은 "사용 중" | **사실** |
| `-마씸` 편중 46.9% | `-마씸` 46.9% + `-수다` 43.6% = **두 종결형이 90.5%**. 100유닛 중 **56개 유닛이 종결어미 2종 이하** | **사실, 문서보다 심각** |
| 복습 간격이 같은 날 반복 클릭으로 승급 | `markRemembered()`가 `due` 검사 없이 `nextIntervalDays()` 호출. 5회 클릭 = 30일 | **사실** |
| 음원 없는 단어에 듣기 문제 생성 | 음원 미보유 108개, `quiz.ts`에 음원 존재 검사 코드 없음 | **사실** |
| 트랙 이름과 유닛 내용 불일치 (6개 나열) | 실제 **9개 유닛**이 트랙 소속과 `themeId` 불일치 | **사실, 범위 더 넓음** |

두 문서의 판단이 갈리는 지점 — **FSRS 도입 시점** — 은 2번 문서 손을 들어준다.
정답 데이터가 틀린 상태에서 스케줄러만 고급화하면 틀린 내용을 더 효율적으로 반복시킨다.
FSRS는 4차로 미룬다.

## 2. P0 — 출시 전 반드시 막아야 할 것

### P0-1. 복수 정답 차단 (읽기 문제)

**문제**: `quiz.ts`의 `pickDistractors()`는 품사와 문자열 편집거리만 본다. 의미는 보지
않는다. "눈곱을 제주말로?" 문항에 `콥`과 `눈콥`이 함께 보기로 뜨면, 어느 쪽을 눌러도
정답인데 코드는 하나만 인정한다.

**계측**: 46개 동의어 그룹(94단어). 20,000문항 중 61건 발생(0.30%).
유닛 1회 학습이 20문항이므로 **레슨당 약 6% 확률로 부정확한 채점**이 일어난다.

**해결 — 최소 침습안 (권장, 1차에서 즉시)**

전면 스키마 전환 없이 지금 구조에 `conceptId`만 얹는다.

```ts
// units.json의 word에 필드 하나 추가
type Word = {
  seq: string;
  jeju: string;
  standard: string;
  conceptId: string;   // 신규. 같은 뜻이면 같은 값
  // ...
};
```

`conceptId`는 초기값을 `standard` 기준으로 자동 생성하되, 동형이의어(같은 표준어지만
실제로는 다른 개념)는 수동 분리한다. `quiz.ts`는 다음 한 줄로 바뀐다.

```ts
// 오답 후보에서 같은 개념 전부 제외
const sameConcept = new Set(
  allWords.filter(w => w.conceptId === word.conceptId).map(w => w.jeju)
);
// pickDistractors의 seen 초기값에 sameConcept 전부 투입
```

**해결 — 구조적 정답 (2차에서)**
`acceptedAnswers: string[]`로 정답을 복수 허용하고, 선택지를 `{id, text, conceptId}`로
바꿔 문자열이 아닌 개념을 비교한다. 동의형 자체를 가르치고 싶다면 "다른 제주어 표현"으로
함께 노출하고 모두 정답 처리한다.

**수용 기준**
- 1,000단어 × 100회 생성 시뮬레이션에서 복수 정답 0건
- 정답 개념이 보기에 정확히 1회 존재
- 회귀 테스트 `quiz.test.ts`로 CI 고정

**작업량**: 소 (conceptId 생성 스크립트 + quiz.ts 20줄 + 테스트)

### P0-2. 뜻이 틀린 단어 즉시 차단

사전 원문 대조 결과, 다음 2건은 **명백한 오류**다. 학습자가 오답을 정답으로 외운다.

| 단어 | 앱 현재 | 사전 원문 | 영문 | 조치 |
|---|---|---|---|---|
| 턱사가리 (4672) | "턱" (+신체 턱 예문) | `턱(理由)` | reason | 뜻을 **"이유/까닭"**으로 수정, 예문 재작성. 확정 전까지 비노출 |
| 선용 (5196) | "사용 중" | `=현용. 형사(形象)` | something as it is now | 근거 없음. **비노출** 후 현용 항목 재확인 |

나머지 4건 판정 (사전 원문·영문·일문 3중 대조):

| 단어 | 현재 | 판정 |
|---|---|---|
| 보태 (2965) | 태반 | **보류 유지**. 한국어 `삼. 태(胎)` vs 영문 `umbilical cord`(탯줄) 충돌. 확정 불가 |
| 감제주시 (4298) | 찐 고구마 | **보류 유지**. `고구마 찌기(澱粉粕)`는 행위+전분박, 영문은 결과물. 혼재 |
| 배량 (7424) | 그덧 | **수정**. `그덧`은 표준어가 아님 → **"그다지/별로"**. 예문 "그덧 다 컸네요"도 비문 |
| 덮개 (467) | 더퍼리 | **수정**. 영문 `a person who is not calm` → **"덜렁대는 사람"** |

**필요한 구조**: 뜻마다 상태 필드를 둔다.

```ts
reviewStatus: "approved" | "provisional" | "blocked"
```

`blocked`는 빌드 산출물에서 제외한다. 지금은 "보류"가 사람 머릿속에만 있고 데이터에는
승인 항목과 똑같이 들어가 있어서, 다음 라운드에 조용히 되살아난다.

**작업량**: 소 (데이터 6건 + 필드 1개 + 빌드 필터)

### P0-3. 음원 없는 단어의 듣기 문제 생성 중단

**문제**: 음원 미보유 108개(신규 107개 중 105개). `buildLesson()`은 전 단어에 듣기 문제를
만든다. 소리가 안 나는 문항은 풀 수 없고 평가 자체가 무효다.

**해결**
1. 빌드 시 `public/audio/{seq}.mp3` 존재 여부를 검사해 `hasAudio` 플래그를 생성
2. `buildLesson()`은 `hasAudio === false`인 단어에 듣기 문제를 만들지 않음
3. 유닛 문항 수가 20개 미만이 되면 읽기 문제로 보충하거나 문항 수를 줄여 표시
4. 통과 기준(70%)은 **생성된 문항 수 기준**으로 계산

**음원 확보 순서** (감사 문서 판단에 동의)
공식 음원 → 화자 녹음 → (TTS는 정답 음원으로 쓰지 않음. 일반 한국어 TTS는 제주어
음운·억양을 왜곡한다. 쓰더라도 "임시 합성음" 표기가 붙은 보조 자료로만)

**작업량**: 소~중 (빌드 스크립트 + quiz.ts 분기 + 통과 기준 조정)

### P0-4. 복습 간격 승급 버그 수정

**문제**: `markRemembered()`가 예정일 도래 여부를 보지 않고 `1→3→7→14→30`으로 올린다.
같은 날 5번 누르면 한 달 뒤 카드가 된다.

**해결**

```ts
// WrongCard에 dueAt 추가
type WrongCard = {
  // ...
  dueAt: number;        // 신규. lastReviewedAt + intervalDays
};

markRemembered: (seq) => {
  const card = get().wrongBySeq[seq];
  const isDue = Date.now() >= card.dueAt;
  set(/* isDue일 때만 intervalDays 승급, 아니면 lastReviewedAt만 갱신 */);
}
```

조기 복습은 간격을 유지한다. SM-2까지 갈 필요는 없고 `dueAt / intervalDays / lapseCount`
분리로 충분하다. FSRS는 이 정리가 끝난 뒤(4차) 검토한다.

**작업량**: 소 (+ 기존 localStorage 마이그레이션 테스트 필수)

## 3. P1 — 콘텐츠 신뢰성의 토대

### P1-1. 예문 원장 분리와 출처·검수 이력 복구

**문제**: 신규 107개는 `units.json`에만 예문이 있고 별도 원장에는 없다. 어느 문장이
말뭉치 원문이고 어느 것이 창작인지 앱 데이터만으로 알 수 없다. 다음 재구성 때 지난
검수 결과가 조용히 덮인다.

**해결**: 단일 원장을 만들고 `units.json`은 여기서 **생성**한다(직접 편집 금지).

```ts
type ExampleRecord = {
  id: string;
  senseId: string;            // 어느 뜻을 보여주는 예문인지
  jeju: string;
  standard: string;
  targetMentions: {           // 표제어가 어디에 어떤 형태로 나타나는지
    lexemeId: string;
    surface: string;
    start: number; end: number;
    matchType: "exact" | "inflected" | "manual";
  }[];
  source: {
    type: "official" | "corpus" | "adapted" | "authored";
    sourceId?: string;        // AI Hub 문장 id, 생활방언 seq 등
    originalText?: string;    // 원문 보존
    editReason?: string;
  };
  review: {                   // 축을 합치지 않는다
    meaning: ReviewStatus;    // 사전 대조
    naturalness: ReviewStatus;// 화자 검수
    translation: ReviewStatus;// 번역 검수
  };
};
```

감사 문서 2번의 지적이 옳다. `native_verified` 같은 **합성 라벨 하나로 뭉치면 안 된다**.
말뭉치 원문이라고 자연스러움이 보장되지 않고, 화자가 승인했다고 사전 의미가 보장되지 않는다.

**현실적 적용 범위**: Irish Sentence Bank처럼 모든 어절에 lemma를 붙이는 건 비용이 과하다.
**목표 표제어만** 명시적으로 연결한다. 신규 107개와 고위험 예문부터 시작한다.

**작업량**: 중 (스키마 + 이관 스크립트 + 빌드 파이프라인)

### P1-2. 종결어미 편중 해소 — "끝만 치환"하지 않는다

**계측**: `-마씸` 46.9% + `-수다` 43.6% = **90.5%**. 100유닛 중 **56개가 종결어미 2종 이하**.
지난 라운드에 40개를 손봤지만 전체 분포는 거의 그대로다. 지금 앱은 사실상
**두 개의 말끝만 가르치고 있다.**

**왜 심각한가**: 학습자가 제주어 종결 체계를 `-마씸`/`-수다` 둘로 오해한다. 질문·명령·
청유·전언의 구분, 친소 관계와 연령에 따른 말투 선택이 통째로 빠진다.

**해결 — 문장을 다시 쓴다**
끝만 바꾸면 화용이 안 맞는 문장이 된다. 다음을 먼저 정하고 문장 전체를 재작성한다.

```ts
speechAct: "statement" | "question" | "command" | "request" | "suggestion"
politeness: "high" | "mid" | "plain"
speaker / listener: 관계 태그
```

**목표 분포**
- 어느 종결형도 전체의 **25%를 넘지 않음**
- 유닛 10문장은 최소 **4종 이상**의 종결 유형 포함
- 초급은 공손 서술·질문·요청 위주, 중급 이후 친근체·간접 표현 확대

**기준 자료**: 생활방언 100편이 실제 분포를 보여준다. 특히 96번 "높이는 말과 낮추는 말"은
같은 뜻의 높임·낮춤을 직접 대조한다. 창작 대신 **실증 자료의 분포를 따른다.**

**작업량**: 대 (900문장 재작성 대상. 단, P1-3 화자 검수와 묶어서 진행)

### P1-3. 화자 검수 게이트 신설

**문제**: 지금까지 QC에 **최종 언어학적 책임자가 없었다.** 데이터 QC는 중복·누락을
잡지만 자연성을 보증하지 못하고, 콘텐츠 담당은 문장을 다듬지만 사전 의미를 바꿀 위험이
있으며, 말뭉치 빈도는 중요도 근거일 뿐 정확한 뜻과 자연스러운 활용을 보장하지 않는다.

**해결**: 배포 전 2인 승인 게이트.

| 역할 | 책임 | 승인 권한 |
|---|---|---|
| 데이터 담당 | 원본 보존, 파싱, 해시, 매핑 | 없음 |
| 콘텐츠 담당 | 표준어 교정, 학습 목표 설계 | 없음 |
| **제주어 화자 검수자** | 자연성·활용·말끝·지역/세대 차 | **필수** |
| **언어 책임자** | 최종 의미·표기 확정 | **필수** |
| PM | 필수/선택 과정, 민감 콘텐츠 노출 | 범위 결정 |

판정 항목 5개 — `뜻 정확성 / 실제로 말할 법함 / 지역·세대 표지 / 활용 정확성 / 번역 대응`.
**하나라도 불합격이면 재작성.** 의견이 갈리면 억지로 하나를 택하지 말고 **지역·세대 변이로
기록하거나 비노출**한다.

**우선 검수 대상**: 신규 107개 전량 → 다의어 전량 → 고빈도 200개 → 생활방언 파일럿

### P1-4. QC 규칙을 데이터로 관리

지금 QC 스크립트는 그때그때 만든 검사가 흩어져 있고, 스크래치패드에 있어 세션이 끝나면
사라진다. 규칙을 데이터로 분리하면 개발자가 아닌 검수자도 규칙을 읽고 고칠 수 있다.

```yaml
id: EXAMPLE_TARGET_SENSE
severity: error
scope: example
description: 예문은 지정된 뜻의 목표 표현을 포함해야 한다
check: targetMention.senseId == example.senseId
badExamples:  ["턱사가리를 신체의 턱으로 사용"]
goodExamples: ["턱사가리를 이유·까닭 뜻으로 사용"]
owner: linguistic-editor
```

**우선 규칙 10개**
1. 중복 `seq` / `lexemeId` / `senseId`
2. `blocked` 상태 뜻의 운영 빌드 포함 금지
3. 뜻과 예문의 `senseId` 일치
4. 퀴즈 보기 내 동일 `conceptId` 중복 금지
5. 표제어의 목표 활용형 연결 여부
6. 음원 파일 존재 및 MP3 무결성
7. 유닛 내 종결어미 편중 (2종 이하 경고)
8. 표준어 뜻이 지나치게 사전적인 항목
9. 출처·라이선스·검수자 누락
10. 생활방언 문장-음원 타임코드 범위

Gramadóir 같은 전체 엔진이나 HTTP 서비스는 **지금 만들 필요 없다.** 저장소에서 실행되는
검증 명령 하나와 사람이 읽는 오류 보고서면 충분하다.

## 4. P2 — 학습 경험 확장

### P2-1. 생활방언 맥락 학습 (파일럿 10편)

이미 확보한 공식 자료 100편(음원 포함)을 쓰므로 **추가 콘텐츠 제작 없이** 고립 예문
학습을 맥락 학습으로 확장할 수 있다. 투자 대비 효과가 가장 좋은 신규 기능이다.

**1차 선정 (현대 활용성 높은 10편)**: 혼저 옵서 / 제주도 인사 / 맨도롱 홀 때 호로록
들여 싸붑서 / 어드레 감디? / 어느제 옵디가? / 어떵 살아 점쑤과? / 무싱 거옌 고릅디가? /
날 도랑 가 줍서 / 높이는 말과 낮추는 말 / 제주도 사투리 인사들

**레슨 흐름 (3~5분)**
1. 상황·제목 확인 → 2. 자막 없이 전체 음원 → 3. "무슨 상황인가?" 의미 문항 →
4. 제주어 자막과 다시 듣기 → 5. 학습한 단어 하이라이트·탭하면 뜻 →
6. 핵심 표현 2~3개 인라인 미니퀴즈 → 7. 표준어 확인 → 8. 전체 듣기·자기평가

**단어 숙련도는 3단계로 시작** (Lute의 1~5단계는 사용자 판단 부담이 크다)
`처음 봄 / 복습 중 / 익숙함` — 퀴즈 결과로 자동 갱신, 필요할 때만 수동 수정.

**인라인 퀴즈**: 기존 `QuizView`를 본문에 넣으면 화면·상태가 무거워진다. 정답 제출과
피드백만 가진 작은 `InlineQuestion`을 별도로 만든다.

**반드시 선행할 것**
- 공공누리 **유형 번호**, 변경 허용, 상업 이용, 출처 문구 확인 (현 README는 "출처표시"만 기재)
- `solution`(표준어 풀이)에 오탈자·직역 존재 → `solutionOriginal` 보존 + `solutionEdited` 신설
- 관광 홍보문·전통 혼인관·외모 평가 편은 **필수 진도에서 분리**하고 시대 맥락 주석

---

### P2-2. 단어 카드 ↔ 생활방언 연결

단어 카드에 "이 단어가 나오는 이야기" 링크를 붙인다. 형태가 변한 용언은 문자열 일치로
못 찾으므로 자동 후보 생성 후 **사람이 승인**한다.

- 단어 카드: "이 단어가 나오는 대화 3개"
- 퀴즈 결과: 틀린 단어가 들어간 생활방언 1편 추천
- 복습 카드: 단어 단독 음원 뒤에 실제 문장 음원 재생

같은 어휘를 새 문맥에서 다시 만나게 해 장기 기억을 강화한다. 1,000단어를 버리지 않는다.

---

### P2-3. 트랙 구조 재설계

**계측**: 9개 유닛이 트랙 소속과 `themeId` 불일치. "동물" 트랙에 자연물·살림살이·밭과 들·
마당과 살림·살림 도구·벌레와 몸이 들어가 있다. 명사 740개 대 형용사 57개라는 데이터
분포상 품사 기반 트랙은 애초에 유지가 불가능하다.

**해결**: 상위 트랙을 **품사가 아니라 생활 장면 기반**으로 재설계한다.

```
나와 사람 / 먹고 마시기 / 집과 마을 / 몸과 건강 / 움직임
느낌과 상태 / 바다와 물질 / 밭과 자연 / 시간과 일상 / 제주 문화
```

품사는 트랙이 아니라 **필터·배지**로 표시한다. 지난 라운드의 테마 변경 자체는 되돌릴
필요가 없다. 트랙 이름과 소속을 함께 바꾸는 것이 맞다.

---

### P2-4. 난이도 재산정

**문제**: 후반 랭크는 "어려운 말"이 아니라 "기존 트랙의 n번째 유닛"이라 배치된 흔적이
크다. 4·5랭크에서 형용사가 사라지고 희귀 직업어·친족어·농경/신앙 명사가 늘어난다.
이는 의사소통 숙련도 상승과 다르다.

**해결**: 단어별 난이도 점수 산정 후 재배치.

```
빈도 35% / 현대 화자 사용성 20% / 표준어와의 형태 거리 10%
의미 구체성 10% / 활용 난이도 10% / 문화·배경지식 10% / 전문가 조정 5%
```

각 랭크에 명사·동사·형용사·담화 표현을 **의도적으로 섞는다.**

## 5. P3 — 이후 검토

### 어휘 구성 재조정
1,000개를 전부 사전 표제어로 채우기보다 층을 나눈다.

```
핵심 600 (생활 필수) + 제주 생활·문화 250 + 선택 심화 150
```

현재 부족한 기능 표현: 요청·허락·거절·사과·감사 / 길찾기·교통 / 가격·수량 /
몸 상태·병원 / 전화·약속 / "다시 말해 주세요" 같은 학습 생존 표현.

### FSRS 도입 (선행 조건 충족 후)
P0-4로 승급 버그를 고치고, 카드 상태와 **불변 복습 로그를 분리**한 뒤, 실제 사용
데이터가 쌓이면 검토한다. `ts-fsrs`는 의존성 0개라 교체 자체는 쉽다.

### 활용형 데이터
"밝은 모음이면 -았수다" 수준 규칙을 바로 코드화해 문장을 **생성하는 것은 위험하다.**
제주어 활용이 표준어 규칙의 단순 변형이라는 보장이 없다. 잘못된 생성기는 지금의 창작
예문 문제를 더 큰 규모로 반복한다. **검수된 관찰 데이터부터** 모은다(생활방언 100편 +
승인된 예문에서 실제 활용형 추출 → 전문가 연결 → 규칙 후보 도출 → 평가셋 → 그 다음).

### 빈도 산출물 정식화
AI Hub 빈도 계산을 스크래치패드가 아닌 버전 있는 데이터로 커밋한다.
`corpusVersion / tokenCount / frequencyPerMillion / matchedForms / scriptVersion` 기록.

## 9. 이 계획의 전제

- **자동화는 후보와 근거를 만들 뿐, 좋은 단어를 최종 결정하지 않는다.** 승인되지 않은
  항목이 앱에 섞이지 않게 막는 것이 자동화의 역할이다.
- **1,000은 제품의 끝이 아니라 "기초 어휘 과정 완료"다.** 1,001번째 단어보다 같은 어휘를
  더 깊은 맥락에서 쓰게 하는 편이 유지율에 유리하다.
- **원문은 지우지 않는다.** 시대적 표현을 삭제해 원문인 것처럼 만들지 않고, 현대판 각색은
  별도 필드로 병행 관리한다.
