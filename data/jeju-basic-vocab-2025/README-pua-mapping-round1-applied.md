# PUA 매핑 high 43개 실제 데이터 반영

`README-pua-mapping.md`에서 정리한 81개 중 **high 등급 43개**를
`data/jeju-basic-vocab-2025/vocab.json`과 `content/lexemes.json`에
실제로 치환 적용했다.

## 적용 전 잡아낸 버그 2개

실제 적용 직전에 결과를 직접 확인하다가 두 가지 실수를 발견해서 커밋
전에 고쳤다.

1. **주변 평문 글자를 복원값에 같이 넣은 실수.** 예를 들어 `U+E1A7`
   (원문 표기 `[PUA]세` = 가위)의 복원값을 `"ᄀᆞ세"`로 적어뒀는데,
   실제 원문에서 PUA 뒤에 이미 "세"가 따로 있으니 치환하면
   `"ᄀᆞ세"+"세"` = `"ᄀᆞ세세"`로 중복되는 버그였다. **PUA 문자 하나에
   대응하는 값만 원자 단위로** 다시 뽑았다(43개 중 31개가 이 문제로
   수정 대상이었음).
2. **겹받침 코드 뒤바뀜.** 옛한글 겹받침 유니코드 코드포인트를 잘못
   매핑해서 `ᄉᆞᆱ다`(삶다)가 `ᄉᆞᆲ다`로, `ᄇᆞᆲ다`(밟다)가 `ᄇᆞᆱ다`로
   뒤바뀌어 있었다. U+11B1(ㄻ)과 U+11B2(ㄼ)를 정확히 다시 매핑해서
   고쳤다.

두 실수 다 실제 데이터에 적용하기 **직전에** 결과를 직접 눈으로
확인(`node -e`로 몇 개 샘플 출력)하다가 잡아냈다 — 커밋된 적은 없다.

## 뜻밖의 부수 효과: 가짜 "confirmed" 12개 자동 해소

`node scripts/audit-word-usage.mjs` 재실행 결과가 바뀌었다:

```
confirmed: 385 -> 373   (-12)
rare:      173 -> 173   (그대로)
unconfirmed: 500 -> 512 (+12)
```

확인해보니, PUA 문자가 들어간 표제어 12개가 **원래는 "ᄒᆞ다"(하다),
"ᄒᆞᆫ디"(한데), "ᄀᆞ르치다"(가르치다) 같은 온전한 단어였는데, PUA가 낀
채로 감사 스크립트에 넘어가면서 (터미널/문자열 처리 과정에서 PUA가
안 보이거나 잘려서) "다", "저", "득", "째기" 같은 의미 없는 짧은
조각만 실질적으로 비교에 쓰였고, 그 짧은 조각이 말뭉치의 전혀 무관한
토큰과 우연히 뜻이 통하는 것처럼 잘못 매칭돼 "confirmed"로 잘못
판정**되고 있었다. 이번에 정확한 옛한글 표기로 고치면서 이 가짜
매칭 12개가 자동으로 사라지고 정확히 "unconfirmed"(말뭉치가 옛한글
표기를 직접 담고 있진 않으니 당연함)로 재분류됐다. **감사 결과가
더 정확해진 것 — 퇴보가 아니다.**
