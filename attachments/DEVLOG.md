# 제주어 학습 앱 — 개발 기록 (DEVLOG)

> ROADMAP.md가 "앞으로 어떻게 할지"를 담은 살아있는 계획서라면, 이 문서는 "지금까지 무엇을 어떻게 했는지"를 시간 순으로 상세히 남기는 기록이다. 의사결정의 배경과 근거, 발견된 문제와 대응을 빠짐없이 남긴다.
> 마지막 갱신: 2026-08-22

## 1. 시작 — 기획 논의

사용자가 제주 방언(제주어) 학습 애플리케이션에 대한 참고 보고서를 첨부하며 "지역관광 활성화에도 도움이 될 것 같다"는 아이디어로 시작. 참고 보고서는 듀오링고 스타일의 게이미피케이션 학습 앱을 제안하며 관광객을 주요 타겟으로 내세웠음.

**초기 논의에서 정리한 것**:
- 국내 기존 제주어 서비스(제주어사전, 제주어왓, 제주어 모바일사전 등) 현황 분석 — 대부분 "검색해서 찾아보는" 수동적 사전형 서비스이고, 매일 열어서 학습하게 만드는 능동적 학습 루프가 없다는 공백을 확인
- 듀오링고의 게이미피케이션 메커니즘(스트릭, 하트, XP, 리그)과 소수 언어 코스 운영 시 겪은 한계(TTS 부재, 콘텐츠 피상성) 검토
- **AI Hub 제주 방언 발화 데이터셋(3,000시간 음성)** 언급 → 확인 결과 승인 절차와 대용량이 필요해 MVP 단계에서는 비현실적이라고 판단, 장기 과제로 분류

## 2. 콘텐츠 소스 발견 — 제주도청 오픈API

사용자가 `OpenAPI활용가이드(제주도청_B01_제주방언사전)_v2.0.hwp` 파일을 첨부. hwp 스킬로 내용을 추출해 확인:

- **서비스**: 제주특별자치도 방언사전 오픈API (`Jeju-OpenAPI-B01`, `JejuDialectService`)
- **인증**: 불필요 (서비스 키 없이 바로 호출 가능)
- **엔드포인트**: `https://www.jeju.go.kr/rest/JejuDialectService/getJejuDialectServiceList?page={n}&pageSize={n}`
- **응답 필드**: 표제어(옛한글 표기 `name`/현대 표기 `siteName`), 뜻풀이(`contents`), 영/일/중 번역, **발음 mp3 다운로드 URL(`soundUrl`)**

`soundUrl`이 존재한다는 게 결정적이었다 — 원어민 발음 오디오를 자체 TTS 없이 바로 쓸 수 있다는 뜻이라, "AI Hub 데이터셋으로 자체 TTS를 만들어야 한다"는 원래 계획을 완전히 대체할 수 있었다.

## 3. Phase 0 — 전체 데이터 수집 및 품질 검증

### 3.1 수집
`scripts/fetch_jeju_dialect.js` 작성 — 페이지네이션으로 전체 7,159개 항목 수집 (`content/jeju_dialect_full.json`). API 문서에 명시된 "초당 최대 30tps" 제약을 감안해 요청 간 250ms 대기, 실패 시 1회 재시도 로직 포함.

### 3.2 실제 curl로 API 동작 검증
- 인증 없이 정상 응답(200 OK) 확인
- `soundUrl`이 실제 mp3 파일(ID3v2.4)을 반환하는 것을 curl로 다운로드해 확인
- **오디오 URL에 CORS 헤더(`Access-Control-Allow-Origin`)가 없음**을 발견 — 이후 앱 구현 방식(`<audio src>` 태그 재생 vs `fetch()` 스트리밍) 결정에 영향
- Referer 체크(핫링크 방지) 없음 확인

### 3.3 데이터 품질 이슈 발견
전체 7,159개를 분석하며 두 가지 심각한 문제를 발견:

1. **분류 코드(`type`) 신뢰 불가**: API 문서(2015년 작성)의 코드표와 실제 2024년 운영 데이터가 어긋나 있음. `DETI`(문서상 "때·기후") 코드가 전체의 **59%(4,200개)**를 차지하는데, 실제로는 "돗-거미"(황금거미) 같은 동물 단어에도 붙어 있어 카테고리로 신뢰할 수 없음. → 이후 콘텐츠 재분류는 원본 카테고리 필드를 무시하고 `contents`(뜻풀이) 기준으로 직접 수행하기로 결정.
2. **PUA(사용자 정의 영역) 문자 오염**: 전체의 **15.5%(1,108개)** 항목의 제주어 표기가 특정 폰트 전용 커스텀 코드(Private Use Area, 예: `U+F43D`)로 저장되어 있어, 해당 폰트가 없는 일반 환경에서는 빈 칸으로 보임. → 학습 콘텐츠에서 전량 제외.

### 3.4 자동 필터링
`scripts/filter_learning_content.js` 작성 — PUA 문자 제외, 뜻풀이 길이(25자 초과 제외), 괄호 섞인 장문 설명 제외, 음성 URL 유무, 카테고리별 상한(`CATEGORY_LIMITS`)을 적용해 **341개**로 1차 축소 (`content/jeju_dialect_learning_v1.json`).

## 4. 로드맵 문서화와 4차례의 외부 피드백 검토

`ROADMAP.md`를 만들어 제품 기획을 문서화하기 시작했고, 사용자가 이 문서에 대한 외부(제3자) 기술/제품 검토를 여러 차례 받아와 반영하는 과정을 거쳤다. 매번 **주장을 그대로 받아들이지 않고 직접 검증한 뒤 타당한 것만 반영**하는 방식으로 진행했다.

### 4.1 초안 (1차)
전체 기획: 문제 정의, 목표/비목표, 타겟 사용자, 정보 구조(5화면), 학습 루프(하트·XP·스트�릭), 기술 스택(Next.js + PWA + Supabase), 4단계 로드맵. 이 시점엔 관광객을 여전히 주요 타겟으로 남겨둠.

### 4.2 2차 개정 — 외부 기술 검토 5개 항목 검증
| 지적 | 검증 방법 | 결과 |
|---|---|---|
| `next-pwa` 유지보수 중단 | 웹서치 | **사실** → `@serwist/next`로 교체 |
| iOS Safari ITP가 7일 미방문 시 localStorage 삭제 | 웹서치 (WebKit 공식 정책 확인) | **사실** → Supabase 익명 인증을 Phase 1으로 앞당기기로 결정 (이후 3차에서 재조정됨) |
| 오디오 CORS로 스트리밍 불가, S3 재호스팅 필요 | **curl로 직접 헤더 조회** | **부분적으로만 사실.** ACAO 헤더는 없지만, `<audio src>` 태그 재생은애초에 CORS 대상이 아님(바이트를 JS로 읽을 때만 CORS 적용) → 재호스팅 불필요 결론 |
| 관광 콘텐츠 데이터 부족 | 논리 검토 | 타당 채택 |
| 스코프 축소(110단어, 부적절 표현 제외) | 논리 검토 | 타당 채택 |

이 라운드에서 처음으로 **v1 타겟을 "제주어 학습자"로 좁히고 관광객은 부차 목표로 격하**하는 방향 전환이 있었다 — API 데이터가 낱말 사전이라 "화장실이 어디예요?" 같은 관광 회화 문장 자체가 존재하지 않는다는 걸 확인했기 때문.

### 4.3 3차 개정 — MVP 우선주의로 전환
사용자가 "일단 mvp 빨리 출시하는 걸 목표로 하자"고 방향을 제시. 이에 따라:
- 콘텐츠 341개 → **MVP는 50개(5유닛×10단어)**로 축소, 나머지는 fast-follow
- Supabase, PWA를 다시 Phase 3/1b로 늦춤 (2차 개정에서 앞당겼던 걸 재조정)
- Phase 1a(MVP)를 "완전한 제품"이 아니라 "최소 동작 가능한 껍데기"로 재정의

### 4.4 두 번째 외부 검토 — 문서 정합성 오류 지적
Supabase 도입 시점이 문서 여러 곳에 다르게 적혀 있는(3장은 Phase 1, 9장/10장은 Phase 3) **자체 모순**을 지적받음 → 검증 결과 실제 오류로 확인, grep으로 전체 재검색해 "Phase 3 도입"으로 통일 정정. 오디오 자동재생 정책(iOS 등은 사용자 제스처 없는 자동재생 차단)도 웹서치로 확인해 반영.

### 4.5 4차 개정 — 제품/UX 심층 검토
가장 실질적인 검토 라운드. 주요 지적과 검증 결과:
- **MVP가 아직도 크다**: 하트·XP·스트릭 없이 "학습→문제→결과"만 먼저 검증해야 한다 → 타당, 채택. Phase 1a를 게임화 없는 "MVP-0"으로, 하트/XP/스트릭은 별도 "1a-2"로 분리
- **하트가 학습을 방해할 수 있다**: 오답을 벌점화하면 "몰랐으니 배웠다"가 아니라 "틀려서 벌받았다"가 됨 → 타당, 채택. **오답 시 하트 차감 대신 즉시 정답 공개 + 레슨 후반부 재출제**로 변경
- **콘텐츠 품질 ≠ 데이터 품질**: PUA·길이 필터는 "깨끗한 데이터"만 걸렀지 "배우기 좋은 단어"는 안 걸렀다 → 가장 타당한 지적. 제안된 16점 정량 스코어링은 "빠른 출시" 기조와 충돌해 **현대성/의미명확성/오디오품질 3항목 체크**로 절충
- **4지선다 오답(distractor) 선정 규칙 부재** → 타당, "같은 유닛 우선 → 같은 품사 우선 → 중복 금지 → 부족하면 전체 풀에서 보충" 규칙 신설
- **문항 C(표기→발음)는 퀴즈가 아니다** → 타당, "퀴즈 2종 + 학습카드 1종"으로 재정의
- **성공지표가 "5명 테스트" 수준** → 타당, activation/completion/repeat/retention 퍼널 + "실제로 단어를 기억하는가" 정성 확인으로 교체
- **판단 보류하고 사용자에게 되돌린 것**: "동사/형용사 대신 동물/자연 유닛이 낫지 않냐"는 제안 — 이건 사실 문제가 아니라 "언어학습 유용성 검증 vs 제주어 고유 재미 검증"이라는 가설 선택이라 AI가 임의로 정하지 않고 사용자 확인을 받음 → **사용자가 기존안(가족·몸·음식·동사·형용사) 유지로 확정**

## 5. Phase 0.5-mini — MVP용 50단어 선별

`scripts/generate_units.js` 작성. 카테고리 자동 필터에만 의존하지 않고 **전체 7,159개 데이터셋에서 직접 재검색**하는 방식으로 진행했는데, 그 이유가 컸다:

**핵심 발견**: 자동 카테고리 필터(`category_name`)로만 골랐다면 "아방(아버지)", "어멍(어머니)" 같은 가장 기본적인 가족 단어가 통째로 누락될 뻔했다. 이 두 단어가 3.3절에서 이미 문제로 지적한 신뢰 불가 카테고리 `DETI`("때·기후")로 잘못 분류되어 있었기 때문이다. `bySeq` 조회로 전체 데이터셋에서 직접 찾아 보강했다.

선별 기준(4차 개정 7.3.1절 기준 적용):
- 교차참조(⇒) 표기로 뜻이 불완전한 항목 제외 (예: "회목→⇒장목")
- 질병/비속어성 신체 항목 제외 (예: "족은한집→홍역", "시드렁똥→된똥")
- 괄호 힌트가 정답을 노출하는 표기 정제 (예: "무끄(묶으)다"→"무끄다", "지프(깊으)다"→"지프다")
- 부적절/비하 표현 제외 (예: "첩각씨→첩", "애기씨→년")
- 한자 병기·옛 표기 정규화 (예: "형(兄)"→"형", "안해"→"아내", "큰삼춘"→"큰아버지")

최종 50개(`data/units.json`):
- 👪 가족과 사람: 아방/어멍/하르방/할망/오라방/성/아시/조카/큰아버지/아내
- 🧍 몸: 가슴/손톱/발톱/입술/맨손/맨발/갈비/귀지/혀끝/멱살
- 🍚 음식: 엿/꿀/소금/두부/고추/시루떡/쌀죽/냉수/조죽/소주
- 🏃 동사: 놓다/펴다/읽다/앉다/쓰다/씻다/묶다/매다/들다/돕다
- ✨ 형용사: 희다/많다/깊다/넓다/아프다/졸리다/무르다/똑똑하다(요망지다)/선선하다/기쁘다

오디오 3개를 실제로 다운로드해 서로 다른 MD5 해시를 가진 정상 mp3 파일임을 확인 (파일 무결성 스팟체크). **단, 50개 전체의 청취 품질 검수는 아직 미완료 상태로 남아있음 (`audioQuality: "pending"`)** — 이번에 사용자가 지적한 "오답을 정답으로 표기" 문제가 여기서 비롯됐을 가능성이 있음 (7장 참조).

## 6. Phase 1a — Next.js 앱 구현

### 6.1 스캐폴딩
`create-next-app`으로 `web/` 디렉토리에 Next.js 16(App Router) + TypeScript + Tailwind CSS 프로젝트 생성.

### 6.2 구현한 것
- `lib/content.ts` — `units.json` 로드, `Word`/`Unit` 타입
- `lib/progress.ts` — localStorage CRUD, 버전 키(`jeju-app:v1`)로 저장, 유닛 순차 잠금 해제 로직
- `lib/quiz.ts` — 문제 생성(퀴즈 A/B + 학습카드 C 랜덤 배치), distractor 선정 규칙 구현
- `components/AudioButton.tsx` — 클릭으로만 재생되는 오디오 버튼 (자동재생 금지 규칙 준수)
- `components/UnitNode.tsx` — 홈 화면 유닛 카드 (잠김/진행가능/완료 3상태)
- `app/page.tsx` — 온보딩(1화면) + 홈(스킬트리)
- `app/lesson/[unitId]/page.tsx` + `components/LessonClient.tsx` — 레슨 화면(문제 진행, 오답 시 정답공개+재출제, 결과 화면)

### 6.3 브라우저로 직접 조작해 실증 (핵심 검증)
로컬 개발 서버를 띄우고 브라우저 자동화 도구로 처음부터 끝까지 직접 클릭하며 검증:
- 온보딩 → 홈(5유닛, 첫 유닛만 열림) 확인
- 레슨 진입, 퀴즈 A(발음→뜻)/B(뜻→표기) 문제 확인
- **일부러 오답을 선택**해 "정답 공개 + 다음" 흐름 확인
- 학습카드(C) 정상 표시 확인
- 레슨 끝까지 진행 → 오답 낸 단어 3개가 **레슨 후반부에 학습카드로 재출제**되는 것 확인 (설계한 재출제 메커니즘이 정확히 동작)
- 결과 화면 → 홈 복귀 시 다음 유닛("몸") 잠금 해제, localStorage에 `{"completedUnitIds":["family"]}` 저장 확인

### 6.4 구현 중 발견하고 고친 버그 2건
1. **정답률 계산 오류**: 결과 화면의 정답률이 학습카드(퀴즈가 아닌 것)까지 분모에 포함시켜, 실제로는 틀리지 않은 단어까지 "틀림"으로 집계되고 있었다. 실제 테스트에서 퀴즈 6개 중 3개 정답(50%)인데 전체 10개 기준으로 나눠 30%로 잘못 표시됨. → 퀴즈로 실제 출제된 단어(`attemptedFirst`)만 분모로 삼도록 수정.
2. **테마 불일치**: 페이지 배경은 시스템 다크모드를 따라가는데 카드 컴포넌트는 라이트 색상으로 하드코딩돼 있어, 다크모드 환경에서 배경(검정)과 카드(흰색)가 부자연스럽게 섞이는 문제 발견 → MVP-0 단계에서는 라이트 테마로 명시적으로 고정 (다크모드 정식 대응은 Phase 1b 이후로 미룸).

### 6.5 실제 오디오 재생 검증 (남아있던 마지막 리스크 해소)
브라우저 JS 콘솔에서 `new Audio(soundUrl).play()`를 직접 실행:
- 로컬 개발 서버에서: "할망"(할머니) 오디오 재생 성공, duration 0.84초, 에러 없음
- **배포된 실제 HTTPS 도메인에서도 재검증**: "아방"(아버지) 오디오 재생 성공, duration 1.38초

이로써 ROADMAP에 "미검증"으로 남아있던 마지막 기술 리스크(오디오 스트리밍 가능 여부)가 실증으로 해소됨. (단, iOS Safari 실기기 테스트는 아직 하지 않음.)

## 7. 배포 — Vercel

### 7.1 Windows 로컬 빌드에서 겪은 문제
`vercel deploy --temporary`(익명 임시 배포, 로그인 불필요) 실행 시 `next build` 자체는 성공하지만, Vercel CLI가 서버리스 함수를 패키징하는 단계에서 심볼릭 링크를 생성하려다 **`EPERM: operation not permitted, symlink` 오류**로 실패. Windows는 기본적으로 관리자 권한이나 개발자 모드 없이는 심볼릭 링크 생성을 제한하기 때문.

### 7.2 해결 — 정적 사이트로 전환
시스템 설정을 바꾸는 대신(개발자 모드 활성화는 관리자 권한이 필요한 시스템 변경이라 배제), **문제의 근본 원인을 우회**하는 방향을 택함: 이 앱은 콘텐츠가 빌드 시점에 이미 고정돼 있어 서버 함수가 애초에 필요 없다는 점에 착안해 `next.config.ts`에 `output: "export"`를 추가하고, 레슨 라우트에 `generateStaticParams`를 구현해 5개 유닛 페이지를 전부 정적 HTML로 미리 생성. 이를 위해 기존에 `useParams()` 훅으로 라우트 파라미터를 읽던 클라이언트 컴포넌트를, **서버 컴포넌트(`page.tsx`, `generateStaticParams` 담당)와 클라이언트 컴포넌트(`LessonClient.tsx`, prop으로 `unitId`를 받음)로 분리**하는 리팩터링을 진행. 결과: 서버리스 함수가 0개인 완전 정적 사이트가 되어 심볼릭 링크 문제 자체가 발생하지 않게 됨.

### 7.3 배포 중 추가로 발견한 버그
정적 export 전환 후 재검증하던 중, **홈 화면의 잠금 표시는 UI일 뿐 실제 라우트 접근은 막지 않는다**는 것을 발견 — `/lesson/food`처럼 URL을 직접 입력하면 아직 잠긴 유닛의 레슨에 그대로 진입됐다. `LessonClient`에 `isUnitUnlocked` 체크를 추가해 라우트 레벨에서도 잠금을 강제하도록 수정.

### 7.4 배포 및 영구화
`vercel deploy --temporary --yes`로 익명 배포 성공 → **https://temporary-fast-silicon-dcdr9pc.vercel.app** (60분 후 만료 예정이었음) → 클레임 URL을 사용자에게 전달 → 사용자가 Vercel 계정으로 클레임 완료, 영구 배포로 전환 확인.

## 8. 사용자 실사용 중 발견된 버그 2건과 수정 (2026-08-22)

사용자가 배포된 앱을 직접 써보고 구체적인 재현 사례를 제공함:
- "발콥/발톱 카드인데 오디오는 손콥이 재생됨. 그다음 입바위/입술 카드에서도 계속 손콥 소리가 남"
- "이 발음의 뜻은? 정답이 두부인데, 보기엔 시루떡/쌀죽/조죽/고추만 있고 두부가 없음"
- "너무 유추하기 쉬운 보기도 있음. 예를 들어 넹수/냉수 같은 건 표기만 다르지 발음이 동일해서 찍어도 맞음"

### 8.1 원인 분석
두 가지처럼 보이는 문제 중 **① 과 ②는 사실 같은 버그 하나**였다.

`components/AudioButton.tsx`에서 오디오 객체를 `if (!audioRef.current) { audioRef.current = new Audio(src); ... }` 형태로 **최초 1회만 생성**하고 있었다. 문제가 바뀌어도 같은 화면 위치의 `<AudioButton>`은 React가 컴포넌트 인스턴스를 그대로 재사용하는데, 이 가드 때문에 `src`가 바뀌어도 새 `Audio` 객체를 만들지 않고 **그 레슨에서 처음 재생됐던 단어의 오디오를 계속 재생**하고 있었다. 그래서:
- "손콥" 학습카드가 먼저 나와 재생되면, 이후 나오는 "발콥"·"입바위" 카드도 전부 "손콥" 소리만 남
- "두부" 문제도 사실 보기엔 정상적으로 "두부"가 포함돼 있었는데, **재생되는 소리가 이전 단어("고추" 등)의 캐시된 오디오**라서 사용자 입장에선 "들은 소리(두부라고 착각)와 보기가 안 맞는다"로 보였던 것

③번(distractor가 너무 쉬움, 예: 넹수/냉수)은 진짜 별개의 문제였다: 제주어 표기가 표준어와 한두 글자만 다른 단어(정확히는 이런 경우가 50개 중 25개나 됨 — 제주어 자체의 특성상 흔함)는, "이 뜻에 맞는 제주어는?" 유형에서 발음을 몰라도 프롬프트와 생김새가 비슷한 보기를 고르면 맞아버려 퀴즈가 무의미해짐.

### 8.2 수정 내용
1. **`components/AudioButton.tsx`**: `useEffect(() => { audioRef.current = new Audio(src); ... }, [src])`로 변경 — `src`가 바뀔 때마다(즉 문제가 바뀔 때마다) 무조건 새 오디오 객체를 생성하도록 고침.
2. **`lib/quiz.ts`**: 레벤슈타인 편집거리 기반 `isTooSimilarToGuess(jeju, standard)` 함수 신설. 편집거리 1 이하면 "생김새로 찍어도 맞는" 단어로 보고 "뜻에 맞는 제주어는?" 유형(B)에서 제외, 발음 퀴즈(A)나 학습카드(C)로만 출제되게 함. (1글자 단어는 편집거리가 항상 1 이하로 나와 오탐이 생기는 걸 발견해 최소 길이 2 이상 조건을 추가로 넣음 — 예: "청/꿀"은 실제로 안 닮았는데 처음엔 잘못 걸러졌었음.)

### 8.3 검증
브라우저에서 `window.Audio`를 몽키패치해 실제 생성되는 오디오 URL을 추적하는 방식으로 재검증:
- 가족 유닛: 문제가 바뀔 때마다 audio URL의 `dialect` seq가 713→7568→7569→2695→544→581로 **매번 다르게** 생성됨을 확인 (수정 전엔 항상 첫 seq로 고정돼 있었을 것)
- 몸 유닛: "손콥"(seq 3139) 다음 "발콥"(seq 3138)으로 각각 정확히 다른 오디오가 매칭되는 걸 확인 — 사용자가 보고한 시나리오를 그대로 재현해 해결 확인
- 음식 유닛: "이 발음의 뜻은?" + "두부" 문제에서 보기가 정확히 "시루떡·두부·소주·쌀죽"으로 표시되어 정답이 포함됨을 확인
- 음식 유닛 전체를 순회하며 넹수·조축·소쥐·옛·청·소곰·고치·곤죽·시리떡 9개 단어 전부 "뜻→표기" 유형으로 출제되지 않는 것 확인 (학습카드/발음퀴즈로만 등장)
- 로컬 개발 서버와 **배포된 프로덕션 도메인 양쪽에서 재검증** 완료

### 8.4 재배포
수정 사항을 다시 빌드해 Vercel에 배포. 이번엔 사용자가 이전 임시 배포를 이미 클레임한 상태라 익명 배포(`--temporary`)가 거부됨 (`This project was claimed successfully. Run vercel login to continue`) → 사용자에게 Vercel CLI 로그인(디바이스 코드 인증)을 요청해 완료 후 `vercel deploy --prod`로 정식 배포. 새 프로덕션 URL: **https://web-lilac-rho-66.vercel.app**
