## 원칙 전환: MVP 우선주의 (2026-08-22, 3차 개정)

지금까지 계획을 두텁게 다듬는 데 시간을 썼는데, 이 자체가 리스크로 판단해 방향을 바꾼다. **"완성도 높은 계획"보다 "지금 당장 배포되어 링크로 써볼 수 있는 것"을 우선한다.** 이하 조정:

- **Phase 1을 "완전한 MVP"에서 "최소 동작 가능한 껍데기(walking skeleton)"로 더 쪼갠다.** 아래 신규 Phase 1a/1b 참조.
- Supabase 익명 인증, PWA(`@serwist/next`) 정교화, 110단어 전량 수작업 검수는 **MVP 필수가 아니라 고도화 항목으로 재분류**한다. 이것들이 없어도 "학습 루프가 도는가"는 검증 가능하다. localStorage 단독 유지의 리스크(iOS 7일 삭제)는 **알고 있는 채로 감수**하고, 사용자가 실제로 7일 이상 재방문 없이 쓰는지 데이터가 쌓인 뒤에 대응한다. (Supabase는 **Phase 3에서만** 도입한다 — 2차 개정에서 "Phase 1으로 앞당김"이라 적었던 부분은 이 3차 개정으로 전부 무효화하고 Phase 3로 되돌린다. 문서 내 다른 절에 남아있던 상충 서술은 아래에서 일괄 정정함.)
- 콘텐츠는 110개 전량 수작업 검수 대신, **정규식 기반 금칙어 필터(1차) + 유닛 5개(50단어)만 우선 출시**로 축소한다. 나머지 유닛은 fast-follow.
- 목표: **"지금부터 코드 작성 시작 → 며칠 내 Vercel 배포 링크 확보"**를 1차 목표로 삼는다.

## 1. 문제 정의

제주어는 2011년 유네스코가 "소멸 위기 언어"로 지정한 언어다. 도민 대상 사전·아카이브(제주어왓, 제주어대사전 등)는 이미 잘 구축돼 있지만, 전부 "검색해서 찾아보는" 수동적 도구다. 매일 스스로 열어서 배우게 만드는 능동적 학습 루프가 없다는 게 실제 공백이다. 이 앱은 그 공백, 즉 **"방대한 자료 vs 습관적으로 쓰게 만드는 제품"** 사이의 간극을 메우는 것이 목적이다.

지역 관광 활성화 기여는 이 프로젝트의 **장기적 기대효과**로만 둔다 (4차 개정: "부차 목표"에서 격하). v1은 관광객이 핵심 타겟이 아니므로, 제품 목표·성공 기준에는 영향을 주지 않는다 — 정책적 기대효과와 제품 목표를 섞으면 나중에 성공 기준이 흔들리기 때문 (아래 4장 참조).

## 2. 제품 한 줄 정의

**제주 방언사전 오픈API 데이터를 학습 카드로 가공하고, 스트릭·하트·XP 기반의 게임화 루프로 매일 5분씩 익히게 만드는 모바일 웹 앱(PWA).**
(※ 이는 장기 v1의 그림이다. MVP-0은 게임화 요소 없이 "학습→문제→결과" 핵심 루프만으로 먼저 검증한다 — 9장, 11장 참조.)

## 3. 목표 / 비목표 (Scope 경계)

### 목표 (v1이 반드시 해내야 하는 것)
- 사용자가 설치 없이 링크 하나로 즉시 학습을 시작할 수 있다 (PWA, 앱스토어 심사 불필요)
- 단어 카드 학습 + 4지선다 퀴즈 + 실제 원어민 발음 청취가 가능하다
- 스트릭이 끊기는 것에 대한 손실 회피 심리를 이용해 재방문을 유도한다
- 진행도가 브라우저를 꺼도 유지된다 (계정 없이도 localStorage로)

### 비목표 (v1에서 의도적으로 하지 않는 것)
- 자체 STT(발음 평가)·TTS(음성 합성) 모델 개발 — 이미 API가 원어민 mp3를 제공하므로 불필요 (Phase 4 이후 검토)
- 문법 교육, 서술형 채점, 회화 시뮬레이션 — 중급 이상 콘텐츠는 v1 스코프 밖
- 지자체·상권 연계 리워드(쿠폰 등) — 별도 협의 트랙, 기술 작업이 아니므로 이 문서의 로드맵에서 제외
- 네이티브 앱(iOS/Android 스토어 배포) — PWA로 충분히 검증한 후에만 고려
- 유료 아이템/인앱결제 — v1은 손실 회피 심리(하트·스트릭)만 차용하고 수익화 장치는 넣지 않음

### 목표 수정 사항 (2차 개정)
"진행도가 계정 없이 localStorage로 유지된다"는 목표는 **iOS Safari ITP 정책(7일 미방문 시 스크립트 저장소 자동 삭제)** 리스크를 안고 있다. 2차 개정에서는 이를 상쇄하기 위해 Supabase 익명 인증을 Phase 1으로 앞당기기로 했으나, **3차 개정(MVP 우선주의)에서 이 결정을 되돌린다.** MVP는 localStorage 단독으로 출시하고, 서버 백업(Supabase)은 실사용에서 데이터 유실이 실제 문제로 확인된 뒤 Phase 3에서 도입한다 (10장 참조). 회원가입 UX 없음이라는 목표 자체는 유지된다.

## 4. 타겟 사용자 (우선순위 순)

| 우선순위 | 세그먼트 | 니즈 | v1에서의 취급 |
|---|---|---|---|
| 1순위 | 제주어 자체에 관심 있는 학습자 (내국인, 해외 동포, 이주민) | 체계적으로 어휘를 늘리고 싶음, 꾸준히 쓰고 싶음 | 메인 학습 코스가 이 세그먼트를 타겟으로 설계됨 |
| 2순위 | 단기 관광객 | 여행 중 재미로 즐길 가벼운 콘텐츠, SNS 공유 | v1에는 별도 트랙 없음. 카테고리 중 "인사/음식" 유닛이 자연스럽게 이 니즈를 커버. 전용 "여행 코스"는 Phase 4 |

**주의**: 애초 기획서(참고 보고서)는 관광객을 전면에 내세웠지만, 실제 만들 v1은 **콘텐츠 소스(API)가 일상 어휘·문법 중심**이라 관광 회화(길찾기, 흥정 등 상황 문장)는 데이터에 거의 없다. 따라서 관광객 전용 기능은 콘텐츠가 확보된 이후로 미루고, v1은 "제주어 자체를 배우고 싶은 사람"에 집중한다. 이게 이번 기획에서 가장 중요한 방향 수정이다.

**Phase 4 관광 코스에 대한 추가 확정 사항 (2차 개정)**: 방언사전 API는 낱말 사전이라 "화장실이 어디예요?" 같은 상황 문장 자체가 존재하지 않는다. 따라서 Phase 4의 관광 코스는 **API 데이터를 재활용하는 게 아니라 별도의 여행 회화 문장 데이터셋을 처음부터 구축**해야 하며, 방법은 두 가지 중 선택: (a) 소규모로 직접 큐레이션(길찾기·주문·인사 상황 30~50문장, 원어민 감수 필요) 또는 (b) 제주관광공사 등 관광 기관과 제휴해 캠페인성 콘텐츠를 공급받는 것. 이 작업은 Phase 4 착수 시점에 별도로 기획하며, 지금 로드맵의 기술 작업 범위에는 포함하지 않는다.

## 5. 제품 원칙

1. **콘텐츠 정확성 > 기능 화려함.** 출처가 불분명한 표현을 넣느니 API 데이터를 있는 그대로 쓰되, 검증 안 된 항목은 표시하지 않는다.
2. **한 세션 = 5분 이내.** 레슨 하나는 8~10문항, 로딩 포함 3~5분 안에 끝나야 한다.
3. **오디오가 텍스트보다 우선.** 방언은 발음이 핵심이므로 모든 단어 카드는 반드시 재생 버튼을 가진다 (음성 없는 항목은 애초에 콘텐츠 파이프라인에서 제외됨 — 이미 적용됨).
4. **로컬 우선, 계정은 나중.** 회원가입 장벽 없이 첫 방문에 바로 학습이 시작돼야 한다.

| 표제어에 PUA(사용자 정의 영역, 특정 폰트 전용 코드) 문자가 섞여 있어 일반 환경에서 깨짐(빈 칸으로 보임) | 1,108/7,159 (15.5%) | 학습 콘텐츠에서 전량 제외 (필터링 완료) |

## 7. 다음 콘텐츠 작업 — Phase 0.5 (미완료, 다음 순서)

341개 낱개 단어를 **앱이 실제로 소비하는 "유닛(Unit)" 단위**로 재구성해야 한다. 유닛은 스킬트리에서 사용자가 클릭하는 하나의 노드이며, 하나의 레슨(8~10문항)에 대응한다.

### 7.1 데이터 모델
```ts
type Word = {
  seq: string;        // 원본 API seq (추적용)
  jeju: string;        // 제주어 표기 (siteName)
  standard: string;    // 표준어 뜻풀이 (contents)
  soundUrl: string;    // 발음 mp3 스트리밍 URL
  eng?: string;        // 영어 대응 (관광객 대상 확장 대비, v1 UI엔 미노출)
  partOfSpeech?: string; // distractor 선정용 품사 태그 (7.4절), 예: "noun"/"verb"/"adjective"
  audioQuality?: 'ok' | 'unclear' | 'noisy'; // 4차 개정 신규: 수작업 청취 검수 결과, "ok"만 MVP에 포함 (7.3.1절)
};

type Unit = {
  id: string;           // slug, 예: "family"
  title: string;         // 화면 표시명, 예: "가족 호칭"

};
```

### 7.3 콘텐츠 규모 및 표현 검수 기준 (결정 완료, 2차 개정)

**규모: v1(장기) 목표는 11개 유닛 × 10단어 = 110단어이나, MVP(Phase 1a)는 그중 5개 유닛 × 10단어 = 50단어만 우선 선별한다** (3차 개정: MVP 우선주의). 이유:
- Phase 1a의 목표는 "핵심 학습 루프가 실제로 작동하는가" 검증이지 콘텐츠 물량이 아님
- 50단어로도 스킬트리 5노드 + 레슨 사이클 검증에 충분
- 나머지 6유닛(60단어)은 Phase 1b(fast-follow)에서 추가, 231개는 그 이후 업데이트 재료로 비축

**부적절/예스러운 표현 제외: 반드시 제외한다 (v1 필수 요건으로 격상).** 사유:
- 시대착오적이거나 비하적 뉘앙스가 있는 항목(예: "애기씨→년")은 향후 네이티브 앱으로 전환 시 스토어 심사 거절 사유가 될 수 있음
- 공공 데이터를 가공한 서비스에 이런 표현이 남아있으면 서비스 신뢰도 자체가 훼손됨
- 기준: 현대 일상 대화에서 성별·혼인상태·나이 등을 비하적으로 지칭하는 뜻풀이(예: 년, 첩 등 멸칭성 단어)는 카테고리·품질 조건을 통과했더라도 수작업으로 제외. 이 작업은 Phase 0.5에서 341→110 선별 시 1차로 걸러내고, Phase 0.5 완료 시점에 최종 목록을 사람이 한 번 더 훑어 확인한다.

### 7.3.1 콘텐츠 "학습 적합성" 검수 (4차 개정, 신규)

지적된 핵심 문제: **PUA·길이·금칙어 필터는 "데이터가 깨끗한가"만 걸렀지 "배우기 좋은 단어인가"는 걸러내지 않는다.** 341개 중 자동 필터를 통과했어도 지나치게 예스럽거나, 뜻이 모호하거나, 오늘날 거의 안 쓰이는 단어가 섞여 있을 수 있다.

**채택한 절충안**: 제안된 16점 정량 스코어링(7개 항목×점수)은 정교하지만 지금 단계에서 341개를 전부 채점하기엔 "빠른 출시" 기조와 충돌한다. 대신 **MVP 50단어를 고를 때만 사람이 3가지를 빠르게 체크**한다:

| 체크 항목 | 통과 기준 |
|---|---|
| 현대성 | 지금도 실제로 쓰이거나 최소한 문맥상 이해 가능한가 (완전히 사어(死語)는 제외) |
| 의미 명확성 | 뜻풀이가 한 가지로 분명한가 (다의어·모호한 설명은 제외) |

이 항목들은 이후 콘텐츠를 341→110, 110→그 이상으로 확장할 때도 동일하게 적용한다. 정량 스코어링 방식은 지금은 도입하지 않되, 콘텐츠 규모가 커져 수작업 검수가 병목이 될 시점(Phase 4 이후)에 재검토한다.

**`Word` 타입에 `audioQuality` 필드는 있으나 (7.1절), 전수 청취 검수는 하지 않기로 결정 (16장, 2026-08-23 재검토)**: 이 오디오는 제주도청이 2015년부터 운영해온 공식 방언사전 서비스의 녹음본이라 발음 정확성은 기관 차원에서 이미 검수됐을 가능성이 높다. 실사용 중 발견된 오디오 문제도 전부 재생 코드 버그였지 원본 녹음 품질 문제는 없었다. 문제 신고 없이 예방적으로 전수 검수하는 건 MVP 우선주의와 맞지 않아, 특정 단어의 문제가 실제 보고될 때만 `/review` 페이지로 확인하는 방식으로 전환한다.

### 7.4 4지선다 오답(distractor) 선정 규칙 (4차 개정, 신규)

지적된 문제: 오답 3개를 완전 랜덤으로 뽑으면 정답이 너무 쉽게 티가 난다 (예: "가족" vs "농사"/"날씨"/"물고기"). `units.json`을 만들 때 단어 배열만이 아니라 **오답 생성 규칙**도 함께 정의한다.

**우선순위 규칙** (문제 생성 시점에 코드로 적용):
1. 같은 유닛 내 다른 단어 우선 (품사·주제가 비슷해 변별력이 생김)
2. 같은 `partOfSpeech`(품사) 우선
3. 정답과 동일한 단어·중복 보기 금지
4. 같은 유닛/품사에서 3개를 못 채우면 전체 50단어 풀에서 무작위 보충

이 규칙은 MVP-0(1a) 구현 시점부터 적용한다 (나중에 추가하는 게 아니라 처음부터 필요한 로직이라는 지적을 반영).

## 9. 핵심 학습 루프 메커니즘

**4차 개정: 게임화 요소를 MVP-0(핵심 루프 검증)와 1a-2(게임화 레이어)로 분리한다.** "학습→문제→결과"가 하트/XP/스트릭 없이도 완전히 성립한다는 지적을 받아들여, 먼저 그것만 검증하고 게임화는 그 위에 얹는다.

### 9.1 MVP-0 (Phase 1a) — 게임화 없는 핵심 루프
| 요소 | 규칙 |
|---|---|
| 오답 처리 | 하트 없음. 오답 시 즉시 정답 공개 + 해당 단어를 레슨 후반부에 재출제 (8장 참조) |
| 유닛 잠금 해제 | 순차적. 이전 유닛을 "완료"(레슨 1회 완주) 해야 다음 유닛 오픈 |
| 진행도 저장 위치 | `localStorage` 단독. Supabase는 Phase 3에서 도입 |
| 진행도 데이터 버전 | **키를 `jeju-app:v1`처럼 버전 명시해서 저장** (4차 개정 신규 — 나중에 저장 구조가 바뀌어도 마이그레이션 가능하도록. 구현 비용 거의 없음) |

## 12. 성공 지표

**4차 개정: "5명이 테스트했다" 식 완료 기준을 행동 기반 퍼널로 교체한다.** 지적대로 이전 지표는 개발 완료 기준이지 제품 성공 지표가 아니었다.

| 단계 | 지표 | 목표(초기 기준선, 데이터 쌓이면 재조정) |
|---|---|---|
| Activation | 첫 방문자 중 첫 레슨을 시작한 비율 | 70% 이상 |
| Completion | 레슨을 시작한 사람 중 10문제를 끝까지 완료한 비율 | 60% 이상 |
| Repeat | 첫날 학습자 중 2일 내 재방문한 비율 | 30% 이상 |
| Retention | D7 재방문율 | 15~20% 이상 |

**정성 체크 (4차 개정 신규, Phase 2 지인 테스트에 포함): "실제로 학습이 발생했는가"**
- 첫 레슨 직후: "방금 배운 단어 중 기억나는 것 하나를 말해보세요"
- 다음 날 재방문 시: "어제 배운 단어 3개 중 기억나는 게 있나요"
이건 통계가 아니라, "앱을 재미있게 썼다"와 "실제로 제주어를 익혔다"를 구분하기 위한 질적 확인이다 — 이 제품의 핵심 가설이 바로 여기 있기 때문.

**Phase 2의 지인 5명 테스트는 통계적 유의성을 노리는 게 아니라 UX 버그 발견용**으로 명확히 규정한다 (4차 개정). 위 퍼널 수치의 진짜 의미는 Phase 2 이후 사용자 수가 늘어난 뒤에 봐야 한다.

## 13. 리스크 및 대응

| 리스크 | 검증 상태 | 영향 | 대응 |
|---|---|---|---|
| 제주도청 API가 예고 없이 중단/변경될 수 있음 (공공 API 흔한 리스크) | 미검증(상시 리스크) | 콘텐츠 공급 중단 | `jeju_dialect_full.json` 원본을 로컬에 보관해뒀으므로 API 재호출 없이도 앱 운영 가능. 단 `soundUrl`은 원본 서버에 의존하므로 API 자체가 죽으면 오디오도 같이 끊김(아래 항목 참조) |
| `soundUrl`에 `Access-Control-Allow-Origin` 헤더가 없음 — **직접 확인함**(curl로 헤더 조회, 2026-08-22) | ✅ 확인됨 | `fetch()`/Web Audio API로 오디오 바이트를 읽는 방식은 브라우저가 차단함 | v1 설계상 `<audio src="soundUrl">` 태그로만 재생하며, HTML 미디어 요소의 단순 재생은 CORS 적용 대상이 아니므로(바이트를 JS로 읽을 때만 CORS가 관여) 이 설계 그대로는 문제 없음. 단, 파형 표시·오프라인 캐싱을 위한 서비스워커 프리캐싱 등 fetch 기반 기능은 앞으로도 이 API에서 불가능 |
| 정부 서버가 향후 정책을 바꿔 hotlink 차단·CORS 추가·트래픽 제한을 걸 가능성 (현재는 Referer 체크 없음을 확인했으나, SLA가 없는 공공 서버라 미래 보장 안 됨) | 부분 검증 — **브라우저 실제 재생은 확인 완료(아래 참조), 모바일 실기기(iOS Safari)는 아직 미검증** | 오디오 재생 불가로 전환될 수 있음 | Phase 1a 구현 중 브라우저(Chromium) JS 콘솔에서 `new Audio(soundUrl).play()`를 직접 실행해 재생 성공 확인함(duration 0.84초, 에러 없음, 정상 종료). `<audio>` 재생 자체는 문제 없음이 실증됨. 남은 건 iOS Safari 등 실기기 확인뿐. 향후 이상 감지 시 mp3를 자체 스토리지(Cloudflare R2 등)로 재호스팅하는 폴백 전환 경로를 Phase 3 기술부채 목록에 기록해둠 |
| iOS Safari ITP가 7일 미방문 시 localStorage를 삭제함 (WebKit 공식 정책, 확인됨) | ✅ 확인됨 | 계정 없는 사용자의 진행도(스트릭 등) 소실 → 게임화 루프 붕괴 | **3차 개정으로 MVP는 이 리스크를 감수하고 그대로 출시.** Supabase 익명 인증은 Phase 3에서 도입 (9장, 10장) |
| iOS Safari 등 모바일 브라우저가 사용자 제스처 없는 오디오 자동재생을 차단함 (오래된 정책, 현재도 유효, 확인됨) | ✅ 확인됨 | "카드 등장과 동시에 자동 재생" 방식으로 구현 시 실기기에서 소리가 아예 안 남 | 모든 오디오 재생은 카드 내 재생 버튼 클릭, 또는 "다음 문항" 버튼 클릭 콜백 안에서만 호출 (8장에 규칙 반영) |
| MVP 50단어(장기 목표 110단어)로는 콘텐츠가 금방 소진됨 | 의도된 트레이드오프 | 반복 학습자의 재방문 동기 약화 가능 | 의도적으로 MVP-0 스코프를 작게 유지(7.3절). 소진 신호가 실사용에서 확인되면 0.5-full(11장)로 즉시 확장 가능하도록 파이프라인을 이미 만들어둠 |

## 16. Phase 1a(MVP-0) 구현 로그

**로컬 개발 서버(Next.js dev)에서 전체 플로우를 브라우저로 직접 조작해 실증 완료**: 온보딩(1화면) → 홈(5유닛, 첫 유닛만 열림) → 레슨(퀴즈 A/B + 학습카드 C + 오답 시 정답공개+후반부 재출제) → 결과 화면 → 홈 복귀 시 다음 유닛 잠금 해제, `localStorage`(`jeju-app:v1`)에 진행도 영속 저장까지 확인.

**구현 중 잡은 버그 2건**:
- 결과 화면 정답률이 학습카드(퀴즈 아님)까지 분모에 넣어 계산되고 있어서, 실제로는 틀리지 않은 단어까지 "틀림"으로 집계되는 문제 발견 → 퀴즈로 나온 단어만 분모로 삼도록 수정 (예: 실제 테스트에서 퀴즈 6개 중 3개 정답=50%였는데 수정 전엔 전체 10개 기준 30%로 잘못 표시됐음)
- 페이지 배경(다크모드 자동 대응)과 카드 배경(라이트 고정)이 서로 달라 테마가 깨지는 문제 발견 → MVP-0은 라이트 테마로 명시적으로 고정, 다크모드 대응은 Phase 1b 이후로 미룸

**Vercel 배포 완료 (2026-08-22)**: `output: 'export'`로 완전 정적 사이트로 전환해 배포함. Windows 로컬에서 `vercel deploy`가 서버리스 함수 패키징 단계(심볼릭 링크 생성)에서 `EPERM` 권한 오류로 실패하는 문제가 있었는데, 애초에 이 앱 콘텐츠가 빌드 시점에 고정돼 있어 서버 함수가 필요 없다는 점에 착안해 정적 내보내기로 전환, 문제를 근본적으로 우회함(레슨 라우트에 `generateStaticParams` 추가, 클라이언트 로직은 `LessonClient` 컴포넌트로 분리). 배포 후 실제 HTTPS 도메인에서 홈 화면과 오디오 재생(아방→1.38초 재생 성공)까지 재검증 완료.
**추가로 발견/수정한 버그**: 홈 화면 잠금 표시는 UI일 뿐, URL을 직접 입력하면 잠긴 유닛 레슨에 그대로 진입되는 라우트 레벨 잠금 누락을 발견해 `LessonClient`에 가드 추가.
**배포 영구화 완료 (2026-08-22)**: 사용자가 Vercel 계정으로 클레임 완료. **Phase 1a(MVP-0) 전 항목 완료.**

**실사용 중 발견된 버그 2건 수정 및 재배포 (2026-08-22)**: 사용자가 실제로 앱을 써보다 "발콥 카드인데 손콥 소리가 남", "두부가 정답인데 보기에 없음" 문제를 보고. 원인은 `AudioButton`이 문제가 바뀌어도 최초 1회 생성한 오디오 객체를 계속 재사용하던 버그(두 증상 다 이게 원인)로 확인, `src` 변경 시 새 오디오를 만들도록 수정. 추가로 "넹수/냉수"처럼 제주어 표기가 표준어와 한두 글자만 달라 찍어도 맞는 문제도 보고받아, 편집거리 기반으로 너무 닮은 단어는 "뜻→표기" 퀴즈 유형에서 제외하도록 `lib/quiz.ts` 수정. 상세 원인·수정·검증 내용은 **DEVLOG.md 8장** 참조. 수정 후 재배포 완료 — **현재 정식 프로덕션 URL: https://web-lilac-rho-66.vercel.app**

**Phase 2 사실상 통과 (2026-08-23)**: 사용자 본인 및 지인들 실사용 결과 "잘 된다"는 긍정적 피드백 확인. iOS 실기기 오디오 재생 여부도 이 과정에서 간접적으로 검증된 것으로 보임(지인들 기기 종류 불명이나 문제 보고 없었음 — 정확히 iOS Safari였는지는 미확인).

**Phase 0.5-full 완료, 콘텐츠 110개로 확장 (2026-08-23)**: 나머지 6유닛(집과 생활·동물·자연과 식물·농사와 하늘·표현·문화, 60단어)을 추가 선별해 `scripts/generate_units.js`에 반영. 이전과 동일하게 카테고리 필드를 신뢰하지 않고 341개 후보를 직접 훑어 교차참조(⇒)·중복·부적절 표현을 제외했고, "정낭"·"불턱"처럼 원문이 설명형 문장인 항목은 짧은 표준어 구로 정리했다. 검증: seq/표기 중복 0건, 오디오 URL 100% 보유, 로컬+배포 환경에서 11개 유닛 전부 브라우저로 순회 확인. 재배포 완료 — URL은 동일(https://web-lilac-rho-66.vercel.app).

**확장 중 발견한 사소한 이슈**: "표현" 유닛은 품사가 다양(부사·감탄사·대명사·수사)해서 distractor 규칙의 "같은 유닛+같은 품사" 우선 조건을 충족하는 후보가 부족해지고, 전체 110단어 풀로 폴백하면서 "여덟/기러기/셋/똑똑하다"처럼 품사가 뒤섞인 보기가 나오는 경우가 있음. 오답은 아니라 기능적 버그는 아니지만 다소 어색함 — 필요시 나중에 손볼 수 있는 개선 후보로 기록.

**오디오 전수 청취 검수 계획 철회 (2026-08-23)**: 애초에 "110개 오디오 전체를 들어보고 품질 확정하자"는 계획을 세웠으나, 재검토 후 철회함. 근거: 이 오디오는 2015년부터 운영된 **제주도청 공식 방언사전 서비스**의 녹음본이라 발음 정확성은 기관 차원에서 이미 검수됐을 가능성이 높고, 지금까지 실사용에서 발견된 오디오 관련 문제(8장)는 전부 재생 코드 버그였지 원본 녹음 품질 문제는 한 건도 없었다. 구체적 문제 신고 없이 예방적으로 110개를 전수 검수하는 건 "문제가 실제 확인되면 대응한다"는 MVP 우선주의 원칙과도 맞지 않아 우선순위를 낮춘다. `Word.audioQuality` 필드와 검수용 `/review` 페이지(`web/app/review/page.tsx`)는 만들어서 배포까지 해뒀으니, **향후 특정 단어의 오디오 문제가 실제로 보고되면 그때 이 페이지로 해당 단어만 확인**하는 용도로 남겨둔다. `audioQuality: "pending"`은 "검수 불필요로 판단됨"으로 사실상 종료 처리.

**남은 것**: "표현" 유닛 distractor 품사 불일치 개선(선택), 정량 지표 측정 체계 마련(12장), 이후 Phase 1a-2(게임화 레이어: 하트·XP·스트릭) 또는 Phase 3 착수 여부 결정.
